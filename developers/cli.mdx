`@revoengine/cli` is the official command-line client for RevoEngine. It requires Node.js 24 or newer.

```bash
npm install --global @revoengine/cli
```

The package installs `revo` as the primary command. `revoengine` remains a compatible alias.

CLI **1.0.32** adds durable Database Operation receipts and verified completion for schema writes, current Endpoint SSE configuration validation, and browser recordings at the selected viewport and frame rate. Schema operations and SSE require Platform 1.7.0; native tests require their matching Platform API. Publishing the CLI does not enable these features on an older instance. Ordinary schema writes remain compatible with instances returning a completed Table synchronously.

## Sign in

```bash
revo auth login
revo auth status
```

Login prompts for an API key, validates it through `/api/v1/me`, and infers the instance bound to the key. Remove the stored default login with:

```bash
revo auth logout
```

Interactive credentials live in the operating-system config directory:

- macOS and Linux: `~/.config/revoengine`
- Windows: `%APPDATA%/revoengine`

Named environment profiles are stored separately from the default login. Logout does not delete those profiles.

## Essential commands

To connect a computer or virtual machine for an Assistant, follow [Connect a terminal](/ai/terminals). After signing in with a personal API key, `revo terminal connect --workspace "$HOME/projects/my-project" --name "Work VM"` creates a pending request. Its owner must approve it in **Settings → Vault → Terminals** from a browser session before the Assistant can use it. Later connections with the same profile and terminal name preserve the device registration; an additional directory becomes a separately approved workspace. Approved online workspaces are available directly to the Assistant. See the terminal guide for connection recovery, background services, browser state and file transfers.

```bash
revo --help
revo -i
revo endpoints
revo search CODE customerId
revo search SIMPLE invoice
revo request GET /api/v1/me
revo request POST /api/v1/endpoints '{"name":"Example"}'
```

`revo request` is a low-level escape hatch for authenticated Platform API calls. Prefer dedicated commands when they provide planning, confirmation, local state, or verification.

## Native tests

CLI **1.0.31 or newer** provides `revo tests list`, `run`, `resume` and `cancel` for captured fixture suites. Test local Component source without publishing it, or select stored suites with `--remote`. See [Native tests](/build/native-tests) for authoring, durable results, CI exit behavior and integration limits.

## Configuration precedence

For the default client, configuration resolves in this order:

1. command flags such as `--url` and `--token`;
2. environment variables;
3. stored interactive configuration;
4. the default API origin.

Named `--from` and `--to` environment profiles resolve independently and are not mixed with the default environment variables.

Supported environment aliases include:

```bash
export REVO_URL="https://api.revoengine.com"
export REVO_TOKEN="$REVO_CI_TOKEN"
revo endpoints
```

`REVO_BASE_URL`, `REVO_API_KEY`, and their `REVOENGINE_*` equivalents are also supported.

<Warning>
  Pass CI credentials from the CI secret store. Do not commit tokens in shell scripts, `.env` files, project metadata, or `.revoengine/`.
</Warning>

## Automation output

Commands that support `--json` emit machine-readable output for CI and review tooling. Human-readable progress and streamed debug logs use stderr where appropriate, leaving the final result on stdout.

The interactive update notifier checks for a newer CLI release at most once every 24 hours. Disable it in CI with `REVO_NO_UPDATE_NOTIFIER=1` or `--no-update-notifier`.

## Submit a long schema change

Normal Table push and full deploy submit durable Database Operations, wait for terminal success, and verify the resulting Table before moving their environment baseline. A failed or unreadable operation prevents later dependent phases from being deployed.

To leave one schema operation running after the command exits:

```bash
revo database-tables push 'Sales/Orders#1234abcd' --yes --async --json
```

The result reports `status: "accepted"` with an `operation` containing `jobId` and its current status. Acceptance is not deployment success. Inspect that ID in Database Operations or with `revo request GET /api/v1/databases/operations/<jobId>`. After `FINISHED`, rerun normal push to verify the portable definition and reconcile the baseline.

For a transport retry across invocations, pass `--idempotency-key <uuid>` with the same target, body and original optimistic version. Admission-only mode requires one explicit Table Stable Key; it cannot prune or use `--all`. Full deploy rejects `--async` because Views, Components and other consumers must wait for schema readiness. Existing reviewed plans and mutation approval requirements continue to apply.
