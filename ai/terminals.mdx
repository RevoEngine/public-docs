An approved terminal lets an Interactive Agent run commands in a connected macOS or Linux environment. The runner can be your computer or a virtual machine running the RevoEngine CLI. The owner approves the terminal before a conversation can use it. Commands run with the runner's operating-system account; its permissions remain an outer limit.

## Connect a workspace

1. Install the [RevoEngine CLI](/developers/cli) on the runner and sign in with a personal API key.
2. Choose an existing directory and run `revo terminal connect --workspace "$HOME/projects/my-project" --name "Work VM"`.
3. Open **AI Agents → Terminals** in the browser and approve the pending terminal. **Workspace Access** is the default command permission. CLI pairing alone does not authorize commands.
4. Keep the CLI connection running, or install its per-user background service. In the Assistant conversation, select **Terminals** in Composer and connect the approved runner.
5. Describe the outcome you want. The Assistant can run workspace commands, inspect output, edit files, install packages and run tests within the permission boundaries below.

The owner can share an approved terminal with selected users, groups, or the instance. Sharing does not change the runner's operating-system account. A conversation can connect multiple approved terminals; its activity shows which runner handled a command.

## Permissions

Terminal permissions have two independent controls in **AI Agents → Terminals → Permissions**. The owner can change either setting while the runner is connected. The runner checks the current grants before each dispatch and stops work that loses required access. The terminal's **Full Access** command setting is separate from the Composer permission mode with the same name.

### Commands

| Setting | Access |
| --- | --- |
| **Workspace Access** (default) | Runs ordinary commands, builds, tests, and edits inside the selected workspace. Writes outside it and host-level actions are blocked unless you approve an exception. |
| **Workspace Access with a temporary exception** | Keeps Workspace Access as the saved setting. An approval permits the requested host-level action once, or permits host-level actions in this chat on this terminal for 15 minutes or one hour. The approved host action can access files outside the workspace. |
| **Full Access** | Allows the Assistant to explicitly request host-level commands without another command-scope approval. Those commands can read, change, or delete anything the runner's operating-system account can access, including files outside the workspace. This setting does not grant network access by itself. |

### Networking

| Setting | Access |
| --- | --- |
| **No Network** | Commands and Browser cannot connect even to localhost unless you approve a temporary network exception. |
| **Local Access** (default) | Permits supported connections to services on the runner's localhost. Internet and other LAN hosts require a temporary network exception. |
| **Full Network Access** | Permits connections to addresses the runner can reach, including the internet and LAN, without another network-scope approval. It does not grant access to files outside the workspace. |

The Assistant requests the command scope and network scope needed for each action. A broader saved grant does not automatically turn an ordinary workspace command into a host command or add network access. For example, **Workspace Access + Full Network Access** can download dependencies and write inside the workspace, but cannot write elsewhere. **Full Access + No Network** permits a requested host-level command to access files available to the runner account, while blocking its network connections. A temporary exception can broaden either dimension without changing the saved settings.

### How the sandbox works

The **workspace** is the directory selected when connecting the CLI runner. Commands execute on that computer or VM, not in a separate RevoEngine-hosted filesystem. For a workspace command, the runner checks the working directory and launches the process with operating-system-enforced file and network restrictions. It can write in the workspace and a temporary working area; the restrictions block writes elsewhere. It can also read the system and toolchain files needed to run programs, so Workspace Access is not a promise that every file outside the workspace is unreadable. Files reached through links remain subject to the boundary. Child processes inherit these restrictions.

On macOS, supported workspace shell actions can connect to localhost under **Local Access**. On Linux, the workspace shell remains isolated from host localhost; the local Browser action is available. Host commands with **Local Access** are unavailable on Linux until that boundary can be enforced. If the runner cannot enforce a required boundary, it rejects the action. Browser actions have their own controlled execution path and follow the networking grant.

**Full Access** removes the workspace file boundary for a host-level command; it does not elevate the runner's operating-system account. Use a dedicated account or VM if the runner has access to other projects, personal files, or credentials. With **Full Network Access** as well, a host-level command can reach external services and transmit data available to that account.

## Approvals for elevated actions

The Assistant explains why an action needs host-level commands or more network access. Under **Restricted** Composer, you decide directly. Under **Auto Review** or **Full Access**, RevoShield first assesses the exact action against your request and sends it to you if it cannot safely approve it. A saved Full Access command grant or Full Network Access grant covers its own dimension regardless of Composer mode. Destructive commands and secret access may still require separate review.

When your decision is needed, you can approve the exact invocation once or grant the missing command or network scope for **15 minutes** or **one hour** on this chat and device. A temporary grant does not change the terminal's permanent settings or authorize a different action after a one-time approval. It ends at expiry, explicit chat disconnect, or a change to the device grant. A short runner reconnect can preserve a still-valid temporary grant for the same chat and device. The runner checks authorization again before input or another action; work requiring an expired or revoked scope is stopped.

The approval shows the proposed command or Browser action and the reason for elevation. Terminal activity in the conversation shows the runner, command, output, and execution status. Ordinary workspace actions within the available grants do not create an approval prompt for every read, edit, or test.

<Warning>
  Full Access gives a requested host-level command broad control over everything the runner account can access. It can modify or delete files outside the workspace. Full Network Access can contact external services. Review the requested scope and destination when an approval reaches you. A terminal grant does not expand operating-system permissions.
</Warning>

## Work with running commands

The Assistant starts a command and waits briefly for its result. A long-running command remains visible under its execution ID; its shell output and final status update in the conversation even if the Assistant continues with other steps. It can check status, cancel, send input, and resize a PTY for interactive programs. A single process may run for up to 59 minutes. Several commands may run at once, subject to runner limits.

If the runner's connection drops, the CLI reconnects and resumes the same execution without starting the command again. If recovery does not succeed, the result is marked uncertain; inspect the target before repeating a command with side effects.

The Assistant can apply a workspace patch without asking for each ordinary edit. Browser actions can navigate to an HTTP(S) page, inspect visible page text, interact with forms, and take a screenshot. The CLI installs the required browser runtime; a separate browser installation is not required. The activity shows the visited URL and page output; a screenshot is automatically attached and shown in the Assistant conversation. The Assistant loads its pixels only when visual inspection is needed. Browser access follows the terminal's network grant and any temporary exception. For a password or similar secret field, the Assistant can request a secure input popup: the value goes directly to the connected browser session and is not included in the model-visible tool call. The Assistant must inspect the resulting page to confirm the action. The browser runs as a dedicated controlled action, separate from the shell's operating-system sandbox.

To show images created by a command or browser screenshot, the Assistant can use `save_image` with up to 32 PNG, JPEG, or WebP files per call from the workspace (240 MiB total per call). It can make more calls for a larger collection. The runner uploads them securely; RevoEngine then attaches them to the conversation. The Assistant loads their pixels in the next model step only when it explicitly needs to inspect them. `save_image` requires **Full Network Access** or a temporary full-network exception.

If a side-effecting command has an uncertain outcome after recovery, inspect its status before trying it again. Starting it twice could repeat its effects.

## Keep a terminal available

The foreground `revo terminal connect` command works while the CLI runs. After approval, you can install a per-user background service on macOS or Linux:

```bash
revo terminal service install --workspace "$HOME/projects/my-project"
revo terminal status
```

Use the same CLI profile and workspace to manage the service.

## Disconnect and revoke

Disconnecting a runner from one conversation removes that conversation's connection. It does not revoke the owner's terminal grant or stop an already-running process. The owner can remove the terminal in **AI Agents → Terminals** to revoke its grant. To remove a locally registered runner, stop its background service first if installed:

```bash
revo terminal service uninstall --workspace "$HOME/projects/my-project"
revo terminal disconnect --workspace "$HOME/projects/my-project"
```

The terminal settings and conversation show activity for authorized viewers. A pending request, offline runner or conversation without a terminal connection cannot execute commands.
