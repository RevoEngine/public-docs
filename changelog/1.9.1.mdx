Build connected dashboard workspaces, choose native platform items, and run one Component element while debugging in Sandbox.

## Highlights

- Open, pin, close and reorder record tabs beside fixed workspace sections while retaining drafts.
- Arrange responsive dashboard content with finer placement, resizable columns, compact tables, badges and native XLSX downloads.
- Execute one JavaScript or TypeScript element explicitly in Sandbox without running its predecessors.

## In detail

## Build connected dashboard workspaces

Combine native content and version-pinned dashboard views in workspace tabs. Open supporting forms in panels, modals or popovers, return selected values, and refresh the intended parent cells after a confirmed action. Root tab changes participate in browser history while mounted forms retain their unsaved drafts. Open several records independently, pin or close them explicitly, reorder them and navigate an overflowing tab strip. Fixed sections can also use sidebar navigation. See [reactive widgets](/operate/reactive-widgets).

## Compose and personalize operational views

Maintain a multi-view workspace in one Component and bind it once to a dashboard. Use a fine placement grid, responsive field layouts, independent spacing and resizable adjacent columns. Compact tables preserve paging and native XLSX downloads without a footer status panel; opt into personal column layouts, hierarchical rows and semantic icon badges. Assistant cards use the shared larger matrix contract. See [table controls](/widgets/tables) and [widget configuration](/widgets/source-configuration).

## Select items with native controls

Use native selectors for Storage, Databases, Components and Preferences instead of building separate lookup forms. Keep the selected item identity available to configured actions. Text section, subsection and callout presets provide a consistent hierarchy for dashboard instructions and supporting content. See [dashboards](/operate/dashboards).

## Run one element in Sandbox

Choose All elements or Selected element in Studio debugging, or send an explicit Sandbox execution mode and exact element key. Selected execution runs that element body without implicit predecessors or dependencies; shared libraries still initialize normally. Endpoint and Job execution continue running the full Component. See [Sandbox execution selection](/developers/sandbox-api).
