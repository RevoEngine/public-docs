RevoEngine 1.7.0 introduces Studio: a shared workspace for developing, testing and deploying application code together with your team and an Assistant. This release also adds native Component tests, configurable AI responses, event streaming and background Database schema operations.

## Highlights

- Introduced Studio with shared coding sessions, team and Assistant collaboration, change review, deployment and rollback.
- Added native JavaScript and TypeScript Component tests, runnable from Studio, the Platform API and the CLI.
- Added Custom Assistant conversations and `agent.createResponse` with saved instructions and text or validated JSON answers.
- Added SSE responses for Endpoints and live Assistant progress from application code.
- Added background Database schema operations with progress tracking and recovery.

## In detail

## Studio

Studio brings code editing, shared sessions, chat and Assistant collaboration into one workspace. Reopen a session with its drafts and tabs, invite teammates or share a read-only view. Drafts remain separate from active application code.

Review changes and test results before deployment. Studio prepares and activates a complete release, with rollback to an earlier ready release. Availability is configured per instance.

Read [Studio sessions](/build/studio-sessions).

## Native Component tests

Create JavaScript and TypeScript test Components with fixtures, assertions and recorded case results. Run them against saved source or local changes from Studio, the Platform API or a CLI worktree. Fixture tests simulate integrations without calling real services; integration tests use the reviewed Studio workflow.

Native-test CLI commands require CLI 1.0.31 or newer.

Read [Native tests](/build/native-tests) and [CLI](/developers/cli).

## Custom Assistant conversations and AI responses

Custom conversations let you choose instructions, context, tools and an answer format before the first message. Use text, JSON or a strict JSON Schema, then keep the same settings across follow-up messages. The browser provides a configuration editor and a saved-contract preview.

Call `agent.createResponse` from application code for focused AI tasks and continue the retained conversation when needed. Technical responses are hidden from ordinary history by default and can be included with **Show Responses**.

Read [Custom conversations](/ai/assistant#create-a-focused-conversation) and [AI responses from application code](/ai/assistant#small-responses-from-application-code).

## Event streaming

Endpoints can send SSE events while a Component runs, with configurable completion events and disconnect handling. Studio and the debugger display emitted events separately from diagnostic logs.

Application code can also stream Assistant progress and reconnect to retained message events without starting another turn. Endpoint event IDs and retry hints alone do not store or replay application events.

Read [Endpoint streaming](/operate/endpoints), the [SSE reference](/low-code/reference/sse) and [Assistant streaming](/ai/assistant#stream-an-assistant-call-from-a-component).

## Background Database schema operations

Database creation and schema updates can run in the background and be tracked through Database Operations. Operations retain their status and recovery information; schema readback is verified before dependent deployment work continues. Existing synchronous calls still return the completed Database.

Read [Database definitions](/operate/database-definitions) and [CLI database workflows](/developers/cli).
