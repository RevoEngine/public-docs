## Configure durable settlement

Create a TypeScript Component with a visible element named **Settlement**. Activate it and select it in a Job template. The Job reads `transactionId` from `api.input('templateInputs')`, where `api.triggerJob()` places per-run arguments. It obtains the original Operation ID and amount from the ledger.

| Job setting | Initial policy | Why |
| --- | --- | --- |
| Execution authority | `payments-runtime` Service Account | Use an account with the required Table, Secret and Storage access. |
| Runtime input | `{}` | The Endpoint supplies the transaction ID when it starts the Job. |
| Concurrency key | `settle-order` | Bounds simultaneous provider work. |
| Concurrency limit | `1` | Serializes retries and duplicate submissions for this example. |
| Automatic retry | Off | Review an uncertain provider outcome in Job History before retrying. |
| Timeout | `60` seconds | Leaves time for the 15-second provider request and local work. |

Use the [current Job limits](/operate/jobs#the-limit-model) for deployment. **4 GiB** is a longer-term product target. The currently enforced maximum is **2 GiB**. Split larger work into resumable stages.

<Tip>
  A remote timeout is ambiguous: the provider might have completed the operation before the connection failed. Query by the provider idempotency/correlation key before retrying the side effect.
</Tip>

### Settlement worker: Secret, HTTP egress, and Storage evidence

Before activating the template, create `PAYMENTS_API_KEY` under **Secrets**, grant the Job Service Account access, and pre-create `payments/settlement-receipts` as a restricted Storage path. Replace the example hostname in the code with an authorized test provider. Use a provider that supports idempotency by transaction ID, lookup by that key, and a confirmed response with `status: "SETTLED"` and a stable `reference` for the same operation.

After provider confirmation, a local transaction marks the ledger and order settled and consumes the reserved amount. The worker then writes the restricted receipt. A Job retry after that database commit uses the stored settlement facts and resumes at the receipt step.

```ts
type Settlement = {
  transactionId: string;
  orderId: string;
  accountId: string;
  amountMinor: string;
  currency: string;
  status: string;
  operationId: string;
  providerReference: string | null;
  settledAt: string | null;
  settlementOperationId: string | null;
  receiptStorageEntryId: string | null;
};

const { transactionId } = api.input('templateInputs') ?? {};
if (typeof transactionId !== 'string' || !util.isUUID(transactionId)) {
  throw new Error('A valid transaction ID is required');
}

const filter = { field: 'transactionId', op: 'eq' as const, value: transactionId };
const initial = await api.getDatabaseDataRow<Settlement>('transactions', { filter });
if (!initial || !['PENDING_SETTLEMENT', 'SETTLED'].includes(initial.status)) {
  throw new Error('Transaction is unavailable for settlement');
}
let settlement: Settlement = initial;

const operationId = api.getOperationId();
const parentOperationId = settlement.operationId;

if (settlement.status === 'PENDING_SETTLEMENT') {
  const provider = await api.httpCall(
    {
      url: 'https://payments.example.com/v1/settlements',
      method: 'POST',
      headers: {
        Authorization: `Bearer ${(await vault.get('PAYMENTS_API_KEY')).revision.value}`,
        'Idempotency-Key': transactionId,
        'X-Correlation-ID': operationId,
      },
      data: {
        transactionId,
        amountMinor: settlement.amountMinor,
        currency: settlement.currency,
      },
    },
    { requestType: 'json', responseType: 'json', timeout: 15_000 },
  );

  const providerData: unknown = provider.data;
  if (provider.status < 200 || provider.status >= 300 ||
      !providerData || typeof providerData !== 'object' ||
      !('status' in providerData) || providerData.status !== 'SETTLED' ||
      !('reference' in providerData) ||
      typeof providerData.reference !== 'string' || !providerData.reference) {
    throw new Error('Provider settlement is not confirmed');
  }
  const providerReference = providerData.reference;

  settlement = await api.transactionDatabase(async (tx) => {
    const ledger = await tx.getDatabaseData<Settlement>(
      'transactions', { filter, take: 1 }, { lock: 'update' },
    );
    const current = ledger.data[0];
    if (!current) throw new Error('Transaction is unavailable');
    if (current.status === 'SETTLED') return current;
    if (current.status !== 'PENDING_SETTLEMENT') {
      throw new Error('Transaction is no longer eligible');
    }

    const order = await tx.getDatabaseData<{ orderId: string }>(
      'orders',
      {
        filter: { and: [
          { field: 'orderId', op: 'eq', value: current.orderId },
          { field: 'reservationTransactionId', op: 'eq', value: transactionId },
          { field: 'status', op: 'eq', value: 'RESERVED' },
        ] },
        take: 1,
      },
      { lock: 'update' },
    );
    const balance = await tx.getDatabaseData<{ balanceId: string; reservedMinor: string }>(
      'balances',
      {
        filter: { and: [
          { field: 'accountId', op: 'eq', value: current.accountId },
          { field: 'currency', op: 'eq', value: current.currency },
        ] },
        take: 1,
      },
      { lock: 'update' },
    );
    const reservedMinor = BigInt(balance.data[0]?.reservedMinor ?? '0');
    const amountMinor = BigInt(current.amountMinor);
    if (order.results !== 1 || balance.results !== 1 ||
        amountMinor <= 0n || reservedMinor < amountMinor) {
      throw new Error('Reserved order and balance require reconciliation');
    }

    await tx.updateDatabaseData('balances', { balanceId: balance.data[0].balanceId }, {
      reservedMinor: (reservedMinor - amountMinor).toString(),
      lastOperationId: operationId,
    });
    await tx.updateDatabaseData('orders', { orderId: current.orderId }, {
      status: 'SETTLED',
      lastOperationId: operationId,
    });
    const changes = {
      status: 'SETTLED',
      providerReference,
      settledAt: new Date().toISOString(),
      settlementOperationId: operationId,
    };
    await tx.updateDatabaseData('transactions', { transactionId }, changes);
    return { ...current, ...changes };
  });
}

const { providerReference, settledAt, settlementOperationId } = settlement;
if (!providerReference || !settledAt || !settlementOperationId) {
  throw new Error('Recorded settlement requires reconciliation');
}

let receiptStorageEntryId = settlement.receiptStorageEntryId;
if (!receiptStorageEntryId) {
  const folder = await storage.ensureFolderPath('payments/settlement-receipts', {
    restricted: true,
  });
  if (!folder.effectiveRestricted) throw new Error('Receipt folder must be restricted');

  const name = `settlement-${transactionId}.json`;
  const entries = await storage.explore({ parentStorageEntryId: folder.storageEntryId, term: name, take: 10 });
  const existing = entries.data.find((entry: { name: string }) => entry.name === name);
  const receipt = existing ?? await storage.putObject({
    parentStorageEntryId: folder.storageEntryId,
    name,
    data: JSON.stringify({
      transactionId,
      orderId: settlement.orderId,
      amountMinor: settlement.amountMinor,
      currency: settlement.currency,
      providerReference,
      settledAt,
      parentOperationId,
      settlementOperationId,
    }),
    mimeType: 'application/json',
    computeStats: 'sync',
    metadata: { transactionId, parentOperationId, settlementOperationId },
  });
  receiptStorageEntryId = receipt.storageEntryId;
  await api.updateDatabaseData('transactions', { transactionId }, { receiptStorageEntryId });
}

return {
  operationId,
  parentOperationId,
  settlementOperationId,
  transactionId,
  providerReference,
  receiptStorageEntryId,
  status: 'SETTLED',
};
```

<Warning>
  Never log `provider.request`, request headers, the Secret value, or an unrestricted provider response. `api.httpCall()` returns diagnostic request data for runtime use; application logs should contain only allowlisted identifiers, status, and timing.
</Warning>

If the HTTP connection times out or the local settlement commit fails, look up the provider operation by `transactionId` before retrying the Job. Retry only while the provider can safely resolve that same idempotency key. If Storage fails after the local settlement commit, retry the Job to rebuild or find the receipt from the stored settlement facts. Save the template and copy its ID back to the Endpoint configuration in [step 2](/tutorials/order-reservation#configure-the-endpoint).
