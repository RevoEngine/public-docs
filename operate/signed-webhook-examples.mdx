Use these Endpoint Component examples to verify signed deliveries before processing
their contents. Pick the example that matches your provider and delivery type.

## Configure your endpoint

1. Create a POST [Endpoint](/operate/endpoints) with modern results, a visible Component result element, and an HTTP JSON response. Select [Raw bytes](/operate/endpoint-bodies) and set the maximum for the entire delivery. The runtime ceiling for an explicit request body is 32 MiB. Your Endpoint and ingress can impose lower limits.
2. Store the integration’s signing secret in instance Vault as `WEBHOOK_SIGNING_SECRET`, unless the example specifies a public key instead. Give the saved executor access to the required secret. For a provider that sends no Revo credentials, configure both [anonymous admission gates](/operate/endpoint-applications#allow-unauthenticated-requests-deliberately) and a dedicated Service Account.
3. Copy one example into the result element. The code reads the Base64 envelope as bytes, validates the provider’s signed input and compares digests in constant time. A valid signature returns a JSON receipt. An invalid, missing or expired signature returns `401`. Complete any provider-required subscription challenge separately and use the provider’s expected acknowledgment in your integration.

Verify the original bytes before parsing JSON or multipart, storing attachments,
or publishing work. Respect the provider’s timestamp semantics and retry window.
Where there is no signed timestamp, signature verification alone cannot prevent
replay. Use a durable deduplication key before downstream effects. During key
rotation, accept only the explicitly configured active and retiring keys.

## Reuse a verifier across Endpoints

Put each provider's verification rules in an active [Library](/build/libraries).
Call the verifier from the receiving Endpoint Component before parsing the event,
calling a business Component, writing to Storage, or starting a Job. The
Library runs inside the receiving Component after Endpoint admission and
request validation.

Create a JavaScript Library named `WebhookVerification` and add this named
export to its `@default` element. The method reads the current request through
`api.input()` and obtains the key from Vault under the Endpoint's execution
permissions. It returns the raw bytes after verifying the signature.

```js title="WebhookVerification · @default"
export async function requireGitHubSignature() {
  const { body, headers } = api.input();
  if (body?.encoding !== 'base64') {
    api.throw(400, { error: 'Expected raw request bytes' });
  }

  const signature = headers?.['x-hub-signature-256'];
  if (
    typeof signature !== 'string' ||
    !/^sha256=[0-9a-f]{64}$/.test(signature)
  ) {
    api.throw(401, { error: 'Invalid signature' });
  }

  const bytes = Buffer.from(body.data, 'base64');
  const key = (
    await vault.get('WEBHOOK_SIGNING_SECRET')
  ).revision.value;
  const digest = await util.hmacAsync(bytes, key, 'sha256', 'hex');
  if (!util.timingSafeEqual('sha256=' + digest, signature)) {
    api.throw(401, { error: 'Invalid signature' });
  }

  return bytes;
}
```

Configure GitHub to send JSON. Start the Endpoint result element with the
Library call, then parse the verified bytes.

```js title="Endpoint result element · verify, then parse"
const bytes = await lib.WebhookVerification.requireGitHubSignature();
const event = JSON.parse(bytes.toString('utf8'));

return { verified: true, action: event.action ?? null };
```

A bad signature returns `401` before the event is parsed. Add business logic
after the Library call. If the logic lives in a separate Component, call it
after verification with [`api.executeComponent()`](/low-code/reference/api/executeComponent).

## URL-bound deliveries

Use the Application address shown in Revo for new subscriptions. When the
provider signs the arriving URL, `api.input().requestTarget.url` preserves the
encoded path, parameter order and repeated query keys. If ingress rewrites
the URL, use trusted integration configuration to reconstruct the provider-facing
address. The runtime omits the full URL and exact query when it recognizes
sensitive query keys. Keep credentials outside signed URL queries.

The examples below cover signed deliveries. Follow each provider’s setup,
challenge and retry rules. For the shared verification flow, MIME limits and
the [Standard Webhooks v1 and v2a examples](/operate/signed-webhooks#example-standard-webhooks),
see [Verify signed webhooks in low-code](/operate/signed-webhooks).

```js title="Adyen · header-signed webhooks"
  api.throw(401, { error: 'Invalid or expired signature' });

  await vault.get('WEBHOOK_SIGNING_SECRET')
```

```js title="DocuSign Connect"

  .filter(
    ([name, value]) =>
      /^x-docusign-signature-[1-9]\d*$/.test(name) &&
      typeof value === 'string' &&
      /^[A-Za-z0-9+/]{43}=$/.test(value),
  )
  .map(([, value]) => value);
if (!candidates.length || candidates.length > 100) {
  api.throw(401, { error: 'Invalid or expired signature' });
}

const key = (
  await vault.get('WEBHOOK_SIGNING_SECRET')
).revision.value;
const expected = await util.hmacAsync(
  bytes,
  key,
  'sha256',
  'base64',
);
if (
  !candidates.some((candidate) =>
    util.timingSafeEqual(expected, candidate),
  )
) {
  api.throw(401, { error: 'Invalid or expired signature' });
}

return { verified: true };
```

## HMAC with a timestamp or delivery ID

<AccordionGroup>
  <Accordion title="Calendly">

Use the subscription’s signing key. Verify the `v1` signature of the timestamp, a dot and the original body. [Provider documentation](https://developer.calendly.com/api-docs/overview/webhooks/webhook-signatures)

```js title="Calendly"
const { headers, body } = api.input();
if (body?.encoding !== 'base64') {
  api.throw(400, { error: 'Expected raw request bytes' });
}
const bytes = Buffer.from(body.data, 'base64');

const signature = headers?.['calendly-webhook-signature'];
if (
  typeof signature !== 'string' ||
  !signature ||
  signature.length > 8192
) {
  api.throw(401, { error: 'Invalid or expired signature' });
}
const parts = signature.split(',').map((part) => part.trim());
const timestamps = parts
  .filter((part) => part.startsWith('t='))
  .map((part) => part.slice(2));
const candidates = parts
  .filter((part) => part.startsWith('v1='))
  .map((part) => part.slice(3));
if (
  timestamps.length !== 1 ||
  !candidates.length ||
  candidates.length > 16
) {
  api.throw(401, { error: 'Invalid or expired signature' });
}
const [timestamp] = timestamps;
if (
  !/^\d{1,12}$/.test(timestamp) ||
  Math.abs(Date.now() / 1000 - Number(timestamp)) > 300
) {
  api.throw(401, { error: 'Invalid or expired signature' });
}

const key = (
  await vault.get('WEBHOOK_SIGNING_SECRET')
).revision.value;
const expected = await util.hmacAsync(
  bytes,
  key,
  'sha256',
  'hex',
  timestamp + '.',
);
if (
  !candidates.some((candidate) =>
    util.timingSafeEqual(expected, candidate),
  )
) {
  api.throw(401, { error: 'Invalid or expired signature' });
}

return { verified: true };
```

<AccordionGroup>
  <Accordion title="SendGrid · signed Inbound Parse">

Enable signature verification and raw MIME delivery in SendGrid Inbound Parse.
Store the public key in Vault as `WEBHOOK_VERIFICATION_PUBLIC_KEY` (PEM or Base64

Add this method to the `@default` element of the `WebhookVerification` Library.
It reads the current request, checks the timestamp and verifies the entire

```js title="WebhookVerification · @default"
export async function requireSendGridSignature() {
  const { body, headers } = api.input();
  if (body?.encoding !== 'base64') {
    api.throw(400, { error: 'Expected raw request bytes' });
  }

  const signature =
    headers?.['x-twilio-email-event-webhook-signature'];
  const timestamp =
    headers?.['x-twilio-email-event-webhook-timestamp'];
  if (
    typeof signature !== 'string' ||
    !signature ||
    signature.length > 8192 ||
    typeof timestamp !== 'string' ||
    !/^\d{1,12}$/.test(timestamp) ||
    Math.abs(Date.now() / 1000 - Number(timestamp)) > 300
  ) {
    api.throw(401, { error: 'Invalid or expired signature' });
  }

  const bytes = Buffer.from(body.data, 'base64');
  const publicKey = (
    await vault.get('WEBHOOK_VERIFICATION_PUBLIC_KEY')
  ).revision.value;
  const valid = await util.ecdsaVerify(
    publicKey, bytes, signature, timestamp,
  );
  if (!valid) {
    api.throw(401, { error: 'Invalid signature' });
  }

  return { bytes, contentType: body.contentType };
}
```
