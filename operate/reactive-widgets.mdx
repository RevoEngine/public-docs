## Pick an interaction

| Operator action | Connect | Example |
| --- | --- | --- |
| Change a filter | Input binding → event → refresh a cell by ID | [Partial refresh](/widgets/refresh) |
| Submit a form | Registered executor → Job acceptance → completion probe | [Form to Job](/widgets/examples/form-job) |
| Select a record | Pass its key → open a registered view → return to the parent | [Table actions](/widgets/examples/table-actions) |
| Act in an Assistant conversation | Return an interactive card with allowed actions | [Assistant card](/widgets/examples/assistant-card) |

The same `rows` structure describes each view. Use [events](/widgets/events), [actions](/widgets/actions) and [bindings](/widgets/bindings) to map input to an effect. Inspect [widget state](/widgets/state) and [$widget context](/widgets/context) when a value needs to survive a refresh. Check [charts](/widgets/charts), [ordered refresh commands](/widgets/refresh#ordered-commands) and [limits](/widgets/limits) for details.
