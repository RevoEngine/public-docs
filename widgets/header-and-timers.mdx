## Dashboard header controls

In the widget settings, **Widget header** exposes **Show refresh** (on by default)
and **Show performance** (off by default). Existing widgets use these defaults
without a migration. The optional boolean fields are `showRefresh` and
`showPerformance` inside `specificCustomWidgetConfig`, or `widgetConfig` when
generating a chat card. Dynamic conversion preserves both settings.

Hiding refresh removes the dashboard header button only: timers, cell actions
and the error recovery button still work. Hiding performance leaves error,
warning and log indicators visible. `refreshTime` configures a whole-widget timer;
per-cell `refresh.intervalSeconds` remains independent. When neither is configured,
the legacy fallback refreshes the whole widget every 6000 seconds (100 minutes).
Per-cell timers suppress that fallback. Timer reads pause while the document or
replacement frame is hidden. These controls do not change access permissions or read-only behavior.

## Assistant card toolbar

Private executable cards expose **Refresh widget** next to copy definition, source code, dashboard conversion and fullscreen. Refresh reads the mounted view with its current input values; it does not ask the Assistant to generate the card again. Shared/report cards remain inactive snapshots.

Generation warnings, errors, logs and measured performance appear as icons in the same toolbar when available. Each icon opens its details in a popover instead of expanding the card body. Performance is adjacent to Refresh widget. A subsequent execution replaces those diagnostics with its own result. Performance uses recorded timing and resource measurements; it does not prove browser rendering or chart performance. Refresh indicates only the current execution and settles when that execution completes.

## Shared content header

The source configuration can add `header: {title, subtitle, actions}`. The same title/actions appear on the widget surface, including a panel. Header actions use the button contract and the active frame's declared targets and input bindings.

| Field | Type | Limit |
| --- | --- | --- |
| `header.title` | Non-empty string | 300 characters. |
| `header.subtitle` | Optional string | 1000 characters. |
| `header.actions` | Button array | Up to 16; unique IDs and accessible labels. |

This configuration fragment belongs beside `sourceType`, not inside a TEXT value:

```json
{
  "header": {
    "title": "Customer workspace",
    "subtitle": "Review current records",
    "actions": [{
      "id": "refreshView", "icon": "fa-regular fa-arrow-rotate-right",
      "ariaLabel": "Refresh customer workspace", "tooltip": "Refresh",
      "on": {"click": {"type": "REFRESH", "target": "*"}}
    }]
  }
}
```

Configure it through the widget's header settings or source configuration. Header visibility, table-footer refresh, content copy and fullscreen are separate controls. Use the shared header for a workspace title instead of making a Markdown heading carry navigation actions.
