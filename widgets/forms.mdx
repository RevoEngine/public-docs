A FORM is a cell containing a `fields` array of INPUT definitions. These are **form fields**, not TABLE columns and not database definitions. Fields use the same INPUT contract and share the frame's ID namespace.

## A read-only form

```js
const ui = api.input()?.$widget ?? {};
const targets = ui.targetIds ?? ['*'];
const wanted = (id) => targets.includes('*') || targets.includes(id);
const rows = [];

if (wanted('quantityForm')) {
  rows.push([
    {
      id: 'quantityForm',
      type: 'FORM',
      label: 'Calculate quantity',
      submitLabel: 'Calculate',
      fields: [
        {
          id: 'quantity',
          type: 'INPUT',
          control: 'number',
          label: 'Quantity',
          value: 2,
          required: true,
          min: 1,
          max: 100,
        },
      ],
      on: { submit: { type: 'REFRESH', target: 'total' } },
    },
  ]);
}
if (wanted('total')) {
  rows.push([
    {
      id: 'total',
      type: 'TEXT',
      value: 'Units: ' + (ui.values?.quantity ?? 2),
    },
  ]);
}
return rows;
```

Initially the result is **Units: 2**. Editing the field leaves the result unchanged until **Calculate** or Enter submits the form. Invalid values block submission. A successful submit refreshes only `total`, preserving the form and its input.

## Configuration

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `id` | string | Required | Form identity. |
| `fields` | INPUT array | Required | Up to 64 controls; nested forms are not supported. |
| `label` | string | Absent | Form heading. |
| `submitLabel` | string | `Apply` | Submit-button text. |
| `on.submit` | Action | No action | Runs after fields have been validated and committed together. |

Do not reuse the form ID for a field. A field's `id` becomes a key in `$widget.values`, so `quantity` is read directly as `ui.values.quantity`, not as `ui.values.quantityForm.quantity`.

To start durable work, use [form → Job → result](/widgets/examples/form-job). Keep the view read-only and place writes in an explicitly registered action.

## Conditional and structured fields

All INPUT controls can be FORM fields, including searchable selects, multiselects, UTC date/time and the [message composer](/widgets/message-composer). A message field commits its whole `{format, body, attachments}` value. Submission waits until its attachments are finalized or removed; an in-progress or failed upload cannot become a ready attachment simply by submitting.

Use `visibleWhen` and `disabledWhen` for applicable fields. Hidden, disabled and conditionally disabled fields are skipped during commit. Values already retained in the frame can still exist, so the server must validate the final action input rather than trusting visibility.

Source-provided `error` supplies field feedback. A refresh with the same INPUT ID and `valueMode: 'initial'` preserves the operator's draft. Use distinct explicit public and internal note fields when only one may be sent outside the workspace.

See [prepare a message without sending](/widgets/examples/message-draft) for a complete read-only FORM example.


## Arrange fields

`FORM.formLayout` accepts `minFieldWidth` from 120–800 pixels and `gap` as none/small/medium/large. The form automatically fits columns to its container. `INPUT.layout.fieldSpan: 'full'` spans the row; `auto` opts into ordinary flow, including for textarea controls. Without an override, textarea and message fields keep their full-width default.
