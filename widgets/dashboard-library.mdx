## Complete widget library

These are the **37 entries in the current Add Widgets palette**. Names below match the app. Most built-in resource grids have no source picker: open the widget, apply its own filter and sort controls, then save the dashboard if that state should reopen. A widget can be visible in the palette yet show **Insufficient permissions** to a viewer without its required role. Resource ACLs remain in force independently of dashboard visibility.

The app can also render **Endpoint Summary** in existing stored dashboard definitions, but it is not an Add Widgets palette entry. The three Database source entries share one renderer for views or use the table renderer as appropriate; the seven AI Usage entries share one renderer with different initial chart settings. Do not substitute a palette label for the stored renderer type when using the Platform API.

## Configure a widget

Every widget has **Widget → Label**, **Presentation → Hide header**, and **Presentation → Hide actions**, plus **Remove**. Hiding the header also clears Hide actions. Configuration opens in a tab beside **Widgets** while the dashboard is unlocked.

| Widget family | Controls and saved behavior |
| --- | --- |
| Database Table / View / Materialized View | The Source picker searches accessible, non-deleted resources of the matching kind. Table selection stores its database ID; View and Materialized View selection store a view ID. Clearing it leaves the widget unconfigured. |
| Agents | Choose one accessible agent in the Agent picker. No selection displays **No agent selected**. |
| Storage | Pick a folder; **Lock path** scopes navigation to that folder; **Disable upload** is the widget's upload control, with effective actions also governed by the viewer's permissions and workspace policy. The picker selects an accessible Storage folder. |
| AI Usage | Choose **Overall**, **Models**, **Tools**, **Skills**, **Most used plugins**, **History** or **All time** and a period. Palette variants preselect a chart but the Analytics selector can change it. Quick periods are 7, 30, 90, 180 or 365 days; a complete custom range is supported up to 366 days. |
| Jobs Performance | Choose a period with the same picker; there is no chart selector or per-template filter in this widget. |
| Execution logs | Configure filters within the Execution logs panel. Applied service, status, user, endpoint/template, Job, IP and date values are stored with this widget; an open end time remains open. |
| Built-in grids | Apply filters and sorting in the rendered grid, then select dashboard **Save**. The stored `gridState` is separate for each widget. The actual columns and filter operators come from that grid; a custom widget `TABLE` does not persist its live filter state. |
| Account charts | These three account charts have no extra source control. Use the common Label and Presentation controls. |

<Warning>
  An unloaded or permission-denied panel is not a valid zero. The dashboard preference grants no access to an embedded resource that the viewer cannot otherwise read.
</Warning>

## Preserve an operator view

Embedded grids retain meaningful filter and sort state in the saved dashboard definition. Use this to build views such as:

- failed Jobs for one settlement category;
- Endpoint latency and Trace evidence for a customer-facing API;
- pending Webhooks for one external integration;
- a restricted Storage folder for an operations team.

Each panel can have a dynamic label and can hide its local header or buttons. File and Storage panels can start at a configured path; path locking and drag controls can prevent a focused workspace from becoming a general file browser.
