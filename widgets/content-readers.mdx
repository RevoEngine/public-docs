title: "Content readers"

Use a reader to display a message, document or compact summary without turning everything into a Markdown heading. Set `presentation` on the existing TEXT cell; the matrix and declarative action contract stay the same. Editing belongs in [inputs](/widgets/inputs) or the [message composer](/widgets/message-composer).

## Choose a presentation

| `presentation.kind` | Cell | Content | Behavior |
| --- | --- | --- | --- |
| `markdown` | TEXT | `value` string | Markdown headings, lists, links and code. |
| `card` | TEXT | `value`; optional `label` | Markdown content with a titled card surface. |
| `plain` | TEXT | `value` | Preserves line breaks without Markdown interpretation. |
| `metric` | TEXT | `value`, optional `label` and `description` | Themed metric card with a visible label, prominent value and supporting description. |
| `badge` | TEXT | `value` label; optional cell `icon` and presentation `tone` | Compact status label using the shared theme. |
| `html` | TEXT | `value` HTML string | Sanitized, isolated, read-only document. |
| `image` | TEXT | `value` HTTPS image URL or supported image data URL | Image with optional `label` and `description`. |
| `code` | TEXT | `value` string | Read-only code editor with a declared language. |
| `properties` | TEXT | `data` object | Key/value description list. |
| `list` | TEXT | `data` array | Displayed labels and optional local reordering. |
| `attachments` | TEXT | `data` attachment records | File cards that emit `rowClick`. |
| `message-list` | TABLE | Flat `data` and stable `rowKey` | Compact conversation selector; see [tables](/widgets/tables#conversation-message-list). |

Omitting `presentation.kind` preserves the ordinary TEXT renderer. A presentation does not execute arbitrary browser code, load a custom component or grant access to the referenced data.

## Reader configuration

| Field | Type | Default or behavior |
| --- | --- | --- |
| `kind` | One of the kinds above | Optional; choose a kind matching the cell. |
| `frame` | `card` | Optional native border and titled section around a reader. |
| `tone` | `neutral`, `info`, `success`, `warning`, `danger` | Semantic theme colors for a card or metric. |
| `copy` | boolean | Opt-in copy for explicit Markdown/card, HTML and plain readers. |
| `fullscreen` | boolean | Independent fullscreen for explicit Markdown/card, HTML, plain and image readers. |
| `scroll` | boolean | TEXT scrolls automatically with a fixed height or `maxHeight`; can be overridden. |
| `scrollControls` | boolean | Enabled unless `false`; up/down controls appear only when content overflows, on hover or keyboard focus. Touch controls remain visible. |
| `minHeight`, `maxHeight`, `maxWidth` | pixels | Optional 1–10000; constrain the cell. |
| `language` | string | Code only; defaults to `plaintext`. |
| `allowImages` | boolean | HTML only; loads permitted remote images automatically when true. |
| `cidImages` | String map | HTML content IDs to authorized fresh Storage URLs, at most 30. |
| `draggable` | boolean | List only; enables reorder controls and `on.change`. |

Copy and fullscreen are separate options. Ordinary TEXT retains its existing renderer defaults; explicit readers enable only the controls configured for their kind. A cell's `height` remains a cell field, outside `presentation`.

Scroll controls sit at the lower edge of the reader body, leaving the title and its actions available above. They move within the loaded content, including an HTML message; they do not refresh the source or load more data.

```js
return [[{
  id: 'triage', type: 'TEXT', label: 'Triage', height: 420,
  presentation: {kind: 'card', copy: true, fullscreen: true, scroll: true, scrollControls: true},
  value: '## Findings\n\nReview the selected message before taking action.'
}], [{
  id: 'metadata', type: 'TEXT', presentation: {kind: 'properties'},
  data: {Status: 'Open', Owner: 'Support team'}
}]];
```

## Isolated HTML

```js
return [[{
  id: 'message', type: 'TEXT', label: 'Customer message', height: 420,
  presentation: {kind: 'html', allowImages: true, copy: true, fullscreen: true},
  value: '<h2>Delivery question</h2><p>Please review the delivery date.</p>'
}]];
```

Use `presentation.frame: 'card'` for a bordered message reader with its title and copy/fullscreen actions aligned in the header. HTML is sanitized and displayed in a sandboxed document. Scripts, inline event handlers, forms, buttons, embedded frames, navigation and content-supplied CSS are removed. The reader applies its own light/dark presentation. It is not a browser page and has no action bridge to the host. Put real controls outside the HTML and use [declared actions](/widgets/actions).

With `fullscreen: true`, the HTML reader fills the available modal body beneath its header and scrolls through the complete message. Its authored cell `height` still controls the embedded reader on the dashboard. Escape or a click outside dismisses the fullscreen view.

With `allowImages: true`, permitted remote HTML images load automatically, including after changing the selected message. There is no separate image-loading button. With the option omitted or false, unrelated remote images remain blocked. For `cid:` images, the authorized source supplies normalized lowercase content IDs in `cidImages` with fresh signed Storage URLs; those authorized images render immediately. Do not copy customer-provided URLs into that map.

The separate `image` reader displays its permitted source directly. Use it for deliberate images or screenshots, not unsolicited tracking images taken from email HTML. It accepts HTTPS URLs and base64 PNG/JPEG/GIF/WebP data URLs. `fullscreen: true` uses the image zoom surface.

## Section header actions

Use the cell's `buttons` for actions beside a section title. A framed HTML, plain-text or image reader places these actions in the same header as copy and fullscreen. The header remains outside the scrolling body. The same pattern is available for titled cards and [conversation lists](/widgets/tables#conversation-message-list).

```js
return [[{
  id: 'triage', type: 'TEXT', label: 'Internal review', height: 420,
  presentation: {kind: 'plain', frame: 'card', copy: true, fullscreen: true},
  buttons: [{
    id: 'refreshTriage', label: 'Refresh', icon: 'fa-regular fa-arrow-rotate-right',
    on: {click: {type: 'REFRESH', target: 'triage'}}
  }],
  value: 'Review the selected record before preparing a reply.'
}]];
```

Buttons use the section cell as their action source and follow the normal registered target, permission and busy-state rules. Configure business actions through [EXECUTE](/widgets/execute); rendering a header button does not grant execution permission.

## Compact status labels

Use `presentation.kind: 'badge'` for a standalone status. Supply its written label in `value`, an optional icon on the cell, and its semantic color through `presentation.tone`:

```js
return [[{
  id: 'status', type: 'TEXT', value: 'Awaiting review',
  icon: 'fa-regular fa-clock', presentation: {kind: 'badge', tone: 'warning'}
}]];
```

Supported tones are `neutral`, `info`, `success`, `warning` and `danger`; the default is neutral. Status remains written text, so color and the optional decorative icon are not its only meaning. For status columns inside a grid, use the [badge column renderer](/widgets/tables#hierarchical-rows-and-badges), which accepts structured badge values in the table's data records.

## Read-only code and structured summaries

The code reader supports `plaintext`, `json`, `html`, `css`, `javascript`, `typescript`, `markdown` and `sql`. It displays source and never executes it:

```js
return [[{
  id: 'receipt', type: 'TEXT', height: 300,
  presentation: {kind: 'code', language: 'json'},
  value: JSON.stringify({status: 'Prepared', recipients: 1}, null, 2)
}]];
```

Properties use `data: {key: value}` and display scalar labels. Lists use strings or records such as `{id, label}`; a record can also supply `title`. Give records stable IDs before enabling `draggable`. Reordering emits ordered string `keys` through `on.change`; it is local until the registered action saves the new order. Keyboard move-up/move-down controls provide the same operation as dragging.

## Authorized file results

A TEXT attachment reader uses `presentation: {kind: 'attachments'}` and `data` records with `key` (or `id`), `name`, `contentType`, optional `size`, `state` and `isInline`. Bind `on.rowClick` to `OPEN_FILE` and pass an attachment identity to a registered read-only `widgetTargets` reader.

The reader must authorize the caller, the selected record relationship and Storage metadata before returning this shape:

| Field | Type | Meaning |
| --- | --- | --- |
| `kind` | `STORAGE_FILE` | Literal result kind. |
| `storageEntryId` | string | Authorized Storage entry UUID. |
| `name` | string | File name, at most 500 characters. |
| `contentType` | string | Actual authorized file content type. |
| `url` | string | Fresh signed Storage URL returned by the authorized source. |
| `expiresAt` | ISO string | Future expiry, at most fifteen minutes ahead. |

The file target returns this object, not a cell matrix. Its configured result element selects the object in a multi-element Component. The host validates the signed-link shape and expiration, and uses one file panel with image/PDF preview where supported. Image zoom and download acquire fresh links through the authenticated Storage API. A URL found in customer HTML or a table row does not establish file permission.

For example, this action fragment belongs on an attachment cell after registering `attachmentReader`:

```js
const action = {
  type: 'OPEN_FILE', target: 'attachmentReader',
  input: {attachmentId: {from: 'event', path: 'row.id'}}
};
```

The input ID is a lookup key for the authorized reader. Do not use clicked text as a signed URL. An unavailable, expired or denied file remains an error; it must not silently become an unrestricted link.


## Shared section presets

TEXT readers accept `presentation.preset: 'section' | 'subsection' | 'callout'`. Section uses the native titled card, subsection uses a more compact header and spacing, and callout adds a semantic accent. These presets reuse the current Revo theme in light and dark mode. Combine a callout with `tone: 'info' | 'success' | 'warning' | 'danger'` when that meaning helps the operator; custom CSS is not part of the contract.

```js
return [[{
  id: 'guidance', type: 'TEXT', label: 'Before continuing',
  value: 'Confirm the selected customer and keep private notes internal.',
  presentation: { kind: 'markdown', preset: 'callout', tone: 'info' },
}]];
```
