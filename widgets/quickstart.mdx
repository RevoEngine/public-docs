Build a name input and a greeting. This example uses no external resources and performs no writes.

## Before you start

You need permission to edit a dashboard and execute its Custom Widget source. [Create a named dashboard](/operate/dashboards#create-a-dashboard-in-the-app), unlock it and add **Custom Widget**.

<Steps>
  <Step title="Configure the source">
    Open **Configure**. Choose **Inline code**, **JavaScript**, and set **Inputs** to `{}`. Keep the view read-only.
  </Step>
  <Step title="Paste the view code">
    Paste this complete body into the widget's code editor:

```js
const ui = api.input()?.$widget ?? {};
const targetIds = ui.targetIds ?? ['*'];
const wanted = (id) =>
  targetIds.includes('*') || targetIds.includes(id);
const name = ui.values?.name ?? 'Ada';
const rows = [];

if (wanted('name')) {
  rows.push([
    {
      id: 'name',
      type: 'INPUT',
      control: 'text',
      label: 'Your name',
      value: 'Ada',
      maxLength: 80,
      debounceMs: 250,
      on: {
        change: { type: 'REFRESH', target: 'greeting' },
      },
    },
  ]);
}

if (wanted('greeting')) {
  rows.push([
    {
      id: 'greeting',
      type: 'TEXT',
      value: name === '' ? 'Enter your name.' : 'Hello, ' + name + '!',
    },
  ]);
}

return rows;
```
  </Step>
  <Step title="Check the result">
    The widget shows **Ada** and **Hello, Ada!**. Type **Grace**: after the input commits, only the greeting refreshes. Clear the input: the result becomes **Enter your name.** The empty string is an intentional value.
  </Step>
  <Step title="Save the dashboard">
    Select dashboard **Save**, then **Lock**. Reloading the page starts again from the source default **Ada**; typing into an input does not change the saved configuration.
  </Step>
</Steps>

## What the example uses

- `rows` is an ordinary JavaScript variable containing the returned matrix.
- `id: 'name'` identifies the input in `$widget.values`.
- `on.change` requests the `REFRESH` action for `greeting`.
- `targetIds` tells the source which cells to return on this execution.
- `??` preserves valid empty strings and zero values, unlike a truthiness fallback.

Continue with [rows, cells and matrix](/widgets/matrix), then [input configuration](/widgets/inputs).

## Editor assistance

Widget code can use the global `DashboardRowInterface[]` type for the returned
matrix and `DashboardElementInterface` for one cell. Choose the cell's `type`
first to get completion for its fields and required properties. These describe
the widget's inner rows; the saved dashboard's layout is configured separately.

```ts
const rows: DashboardRowInterface[] = [
  [{ type: 'TEXT', value: '## Summary' }],
];
return rows;
```

In JavaScript, put `/** @type {DashboardRowInterface[]} */` immediately above
`const rows = ...`. Add `// @ts-check` at the top of the source for local JavaScript
diagnostics when needed. No imports or namespace prefixes are required.

Changing the inline source language switches completion and checking while preserving
your source text. Adjust the code syntax for the selected language.

Monaco and the RevoEngine VS Code extension provide the same starting snippets:
`revo-widget`, `revo-table`, `revo-chart`, `revo-form`, `revo-button` and
`revo-widget-input`. In VS Code, refresh editor types after upgrading the platform.
Types and completion help while writing; execution and render checks still apply.
