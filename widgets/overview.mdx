A Custom Widget is a low-code function whose result describes a small user interface. It can display data, collect input, refresh a result, open a detail view or launch a registered action. The same interaction model is used in dashboards and private Assistant cards.

Start with a static result. Add one input and one refresh action before introducing background Jobs or nested views.

## The four parts

| Part | Written by | Responsibility |
| --- | --- | --- |
| Source configuration | Widget author | Selects Inline code or a Component, configured inputs and runtime limits. |
| Returned matrix | View code | Describes rows of cells and their content. |
| Interaction state | Widget runtime | Retains committed inputs, drafts, selected keys and navigation frames. |
| Target registries | Widget author | Select reviewed view sources and action executors by name. |

The source runs on the server; the browser renders the result. An `on` entry describes an action as data. It does not contain a browser callback.

## Rich content and message workspaces

Use [content readers](/widgets/content-readers) for isolated incoming HTML, images, code, properties, lists and authorized file previews. The [message composer](/widgets/message-composer) adds Markdown editing and Storage attachments; preparing an email and sending it are separate operations. Paged [tables](/widgets/tables), [conditional forms](/widgets/forms) and independent [child views](/widgets/navigation) can be combined without replacing the existing widget format.
