A Studio session is a durable workspace for changes spanning several Components, tests and supporting files. Humans, Assistants and authorized Agents can work in the same session. Saving a session preserves a draft; it does not deploy Components or activate their runtime.

## Session lifecycle

| Stage | What is durable | What users should expect |
| --- | --- | --- |
| Local draft | Unsaved working buffers on this device | Start editing immediately; save before relying on recovery |
| Saved session | Captured source, supporting files and observed base versions | Reopen or collaborate without deploying |
| Tested candidate | Evidence for the exact captured code and dependencies | Retest changed source; fixture tests do not authorize live effects |
| Frozen review | Candidate and approval evidence | Resolve permissions, invalid source and version conflicts |
| Committed source | Reviewed source changes | Active runtime is still unchanged |
| Prepared release | Ready or failed preparation result | HTTP success alone is not a ready runtime |
| Activated | Selected active runtime generation | Session becomes archived; further work uses a child session |

## Preserve working changes

Use [Save and resume a workspace](/build/studio-session-workspace) for Components, Scratch, shortcuts, conflicts and saved layouts.

## Ask the Assistant to edit

The [session authoring flow](/build/studio-session-workspace#ask-the-assistant-to-edit) keeps AI edits in the selected draft. Opening an Assistant draft does not send a message or deploy code.

## Collaborate and share

[Participant roles, Studio Chat and AI threads](/build/studio-session-collaboration) have distinct access boundaries. A read-only link does not grant editing rights or publish earlier private Assistant history.

## Test and review

[Test the exact candidate](/build/studio-session-review), inspect current evidence, then freeze and review it. Source and dependency changes require fresh applicable evidence.

## Commit and activate

[Prepare and activate the release](/build/studio-session-release). Inspect its actual status, handle a changed active generation, and use rollback or Continue work where appropriate. Saving, committing source and activating remain separate operations.
