## Authoring practices

Validate input before external calls and enforce business constraints in the executing Component. Use Libraries for shared in-process rules, Components for execution units, Endpoints for HTTP boundaries and Jobs for durable work. Resolve Secrets at runtime and avoid copying them into logs or results.

Return stable execution, operation or resource IDs so the next caller can follow evidence. See [runtime basics](/low-code/overview), [Library authoring](/build/library-authoring), [Secrets](/operate/secrets) and [Observability](/operate/observability).

## Production review checklist

- Validate input at the public boundary and enforce business rules again in the executing Component.
- Bound reads, page sizes, file batches, execution time and [concurrency](/patterns/low-code-concurrency).
- Make [retries and replays](/patterns/idempotency) safe for each business effect, including payments, messages and database transitions.
- Keep [database transactions](/patterns/transactions) short. Run external calls and file transfers outside them.
- Give the execution account only the roles and resource access the Component requires.
- Resolve [Secrets](/operate/secrets) at runtime and keep their values out of logs and results.
- Return stable execution, operation or resource IDs so the caller can follow the result in [Observability](/operate/observability).
- Document how operators distinguish acceptance from completion, verify [uncertain outcomes](/patterns/retry-and-uncertainty) and recover safely.
