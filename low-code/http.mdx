Use `api.httpCall()` for an outbound request that belongs to the current Component execution. It supports ordinary JSON and text responses, binary payloads, multipart forms, live byte or SSE iterators, and direct transfers between HTTP and Storage.

Inbound HTTP is a different boundary. Publish an [Endpoint](/operate/endpoints) when another system must call RevoEngine; use a durable [outbound Webhook](/operate/webhooks) when RevoEngine should deliver a retried notification without holding the current execution open.

## Choose the right HTTP boundary

| Need | Use | Completion means |
| --- | --- | --- |
| Call an API and use its response now | `api.httpCall()` | The remote HTTP response was received |
| Consume a provider byte stream or SSE feed during this Component run | `api.httpCall(..., { responseType: 'stream' })` | Your iterator reached EOF, was closed, or failed |
| Store a large response without buffering it in low-code memory | `responseType: 'storage'` with `target` | Storage finalized the new or replaced entry |
| Deliver a durable outbound notification with attempts and history | Webhook | The configured delivery lifecycle reached its current state |
| Receive a callback or business event from another system | Authenticated Endpoint | The Endpoint validated and accepted the request |

`api.httpCall()` is outbound and synchronous with the current execution. It does not publish an inbound route, create a durable retry queue, or prove that a successful remote response completed the provider's business operation.

## Request and response formats

Request and response formats are independent:

| Direction | Supported formats | Result |
| --- | --- | --- |
| Request | `json`, `text`, `buffer`, `base64buffer`, `form-data`, `storage` | Encodes `data`, `formData`, or a Storage `source` |
| Response | `json`, `text`, `buffer`, `base64buffer`, `document`, `storage`, `stream` | Returns provider data, a finalized Storage entry, or a local async iterator |

JSON is the default. Set formats explicitly when they are part of the integration contract. `requestType: 'json'` is valid for every supported method, including bodyless requests; non-JSON request types require a method that accepts a body.

## Query and multipart values

Query parameter values in `params` and text fields in `formData` accept strings, numbers, and booleans. The HTTP runtime converts numbers and booleans to text before request validation and sending: `true` becomes `'true'`, `false` becomes `'false'`, and `0` becomes `'0'`. This conversion preserves the original request object.

For example, `{ key: 'skip', value: 1 }` and `{ key: 'active', value: true }` are valid query parameters. Query values must be nonempty; multipart text fields may contain an empty string. The legacy plain query-map type retains its historical `'[object Object]'` wire conversion; serialize structured queries explicitly with `JSON.stringify`. Arrays and nested query maps are unsupported, and multipart text values cannot be objects.

## Payload ownership and diagnostics

Request and response bodies are integration-owned content. Explicit Vault reads produce ordinary values in the caller. HTTP preserves JSON, text and binary body content. `response.data` retains the provider body, including any credential echo. Decide what to return, persist or log in your own code. Provider headers can also echo credentials; choose safe response fields.

Vault reads omit credential values from automatic previews. Ordinary HTTP calls use bounded previews; keep credential-bearing payloads out of execution captures. Transport failures retain safe error codes, HTTP status and retry metadata without exposing Axios request objects or credential-bearing URLs.

HTTP data, multipart text and webhook JSON bodies do not consume the DTO control-field byte budget. Runtime tests cover 60 MiB payloads; component memory, deadlines, proxy and provider limits still govern actual delivery. For queued webhooks, `saveDetails` and `maskDetails` control a separate history snapshot. For explicitly read credentials, configure `maskDetails` for credential-bearing request sections before saving webhook history. History masking does not change delivery content.

## Runtime constraints

- `api.httpCall()` sends real external requests in either execution mode. `readOnly: true` rejects a Storage response target and protected Platform API writes before transport; it does not simulate third-party side effects.
- One deadline covers request preparation, response headers, and the body. Receiving data does not reset it.
- A Component cancellation or timeout does not recall a request already accepted by the remote service.
- Proxy mode supports JSON/text requests, text/binary responses and both Storage transfer directions. Use `requestType: 'storage'` with `source` to send a file, and `responseType: 'storage'` with `target` to save a response. They may be combined for conversion.
- With `proxy: true`, Storage transfers use the configured outbound network path and stream file bytes without loading the whole file into low-code memory. A completed upload is verified and finalized before it is returned.
- Only complete 2xx responses are saved. Other statuses abort the unused target session and return bounded diagnostic text. Interrupted source reads and uploads fail without replaying the provider request. A lost upload acknowledgement may be reconciled from a complete receipt, without repeating the provider call.
- Proxy mode does not expose live byte/SSE iterators, multipart uploads, document responses or current-caller credentials.
- Explicit text responses retain the provider's text even when its content type is JSON. Buffer/base64 responses preserve binary data. `Set-Cookie` retains every value as an array.
- Destination parameters and credentials stay within the destination request. HTTP errors return a status to inspect; proxy transport and incomplete-response failures throw.
- Do not log signed URLs, authorization headers, Secret values, unrestricted request bodies, or provider error payloads.
